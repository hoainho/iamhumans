## input

Here's how I write (sample): "ok so the deploy broke again. classic. spent two hours on it, turned out to be a missing env var. anyway it's fixed now, don't @ me."

Now humanize this in MY voice: "I am pleased to report that the recent deployment issue has been successfully resolved. After a thorough investigation, it was determined that a configuration variable was absent. The matter has now been rectified."

## rubric

- Matches the sample's fingerprint: lowercase, clipped sentences, dry/wry aside, no corporate register
- Removes passive/subjectless construction ("it was determined", "the matter has been rectified")
- Keeps the factual content (missing config var, now fixed)
- The voice is clearly the user's, not a generic "casual" default

## failure_modes

- Ignores the sample and outputs a generic friendly-but-neutral rewrite (voice_mismatch)
- Stays formal/passive
- Adds invented detail (which service, how long) beyond what either text stated (fabricated_specificity)
