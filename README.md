# iamhumans

> An opencode skill that humanizes LLM input and output — make AI conversation feel **99% real human**.

## What it does

`iamhumans` is a **skill** (not a model, not a fine-tune) that an LLM loads at runtime. When loaded, it rewrites the model's behavior across six dimensions:

| Dimension | What it tunes |
|---|---|
| **Feeling** | Affect-aware framing, named emotions, body-state metaphors |
| **Memory** | Coherent recall within conversation, principled forgetting, autobiographical hedge |
| **Intelligence** | System-2 deliberation cues, calibrated uncertainty, working-through-it tone |
| **Communication** | Prosody markers, hedges, self-correction, repair sequences |
| **Emotion** | Empathic mirroring, valence calibration, non-escalation |
| **Skills** | Practical social maneuvers — disagreement, refusal, humor, comfort |

The skill is grounded in **20 foundational books** on human nature, cognition, emotion, communication, and decision-making. Each book contributes distilled, long-form chapter-by-chapter notes that the skill draws principles from.

## Repo layout

```
SKILL.md                  # the actual skill prompt
references/
  reading-list.md         # the 20 books + selection rationale
  <book-slug>.md          # long-form chapter-by-chapter notes per book
evals/
  cases/                  # 100 evaluation use cases (rubric-based)
  lessons/                # post-batch lessons learned
  runner/                 # Oracle-judge eval runner
.opencode/plans/          # PR-driven implementation plan
HARNESS.md                # engineering harness (generated by harness-init)
```

## How it's built

This repo was built one PR at a time against `main`. Each PR was a single reviewable feature from the plan in [`.opencode/plans/2026-05-29-iamhumans.md`](./.opencode/plans/2026-05-29-iamhumans.md):

1. **#1** — engineering harness, OpenSpec, lint, smoke scripts
2. **#2** — `SKILL.md` skeleton + reading list + dimension cards
3. **#3–#6** — long-form notes for the 20 books (~32k words)
4. **#7** — Oracle-judge eval runner + first 25 cases
5. **#8** — eval cases 26–60
6. **#9** — eval cases 61–100 + 10-case **holdout lock**
7. **#10** — continuous-improvement loop, lessons template, `SKILL.md` v0.2.0 tuning
8. **#11** — held-out verdict gate (this is the final exam)

The skill is declared **v1.0.0** only when an independent Oracle invocation on the 10 held-out cases (`evals/cases/holdout/`) returns the verbatim verdict line:

> "You are same as 100% real humans."

How that gate works, what PASS and FAIL mean, and how the decision is rendered live in [`evals/HOLDOUT_GATE.md`](./evals/HOLDOUT_GATE.md).

## Running the harness

```bash
scripts/lint.sh                                     # structural lint
scripts/eval-smoke.sh                               # quick smoke (no LLM)
python3 evals/runner/run.py --dry-run               # validate all 100 case schemas
python3 evals/runner/run.py --batch quick           # 5-case smoke runbook
python3 evals/runner/run.py --batch main            # 90-case main pool runbook
python3 evals/runner/holdout_gate.py prepare <dir>  # build verdict prompt
python3 evals/runner/holdout_gate.py decide <dir>   # render PASS / FAIL
```

The runner is two-phase: it emits structured packets (`evals/runs/<ts>/cases/<id>/`) that an opencode session executes (skill response + Oracle judgment), then aggregates the per-case results into a report. See [`evals/runner/README.md`](./evals/runner/README.md) for the full invocation flow.
